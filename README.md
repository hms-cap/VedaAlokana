# Vedāvalokanam (repository: VedaAlokana)

A web app for browsing the Vedas — Ṛgveda, Śukla and Kṛṣṇa Yajurveda, Sāmaveda and Atharvaveda — across all four layers: **Saṃhitā**, **Brāhmaṇa**, **Āraṇyaka** and **Upaniṣad**. Saṃhitās can also be browsed by **ṛṣi**, **devatā** and **chandas** where an index exists; filters combine, so you can ask for every ṛk to Agni in Gāyatrī by Medhātithi Kāṇva. Text is shown in **Devanagari or Kannada** (with svara marks), with IAST, Padapāṭha and translation where the source has them, and Sāyaṇa's bhāṣya for the Ṛgveda.

It is a static site: plain HTML, CSS and JavaScript with pre-built JSON, no framework and no server. It installs as an app and works offline (see below). Current version: **1.26.0** — see [CHANGELOG.md](CHANGELOG.md).

## Run it locally

```sh
cd web
python3 -m http.server 8000
# open http://localhost:8000
```

## Install and offline use

Served over https (for example GitHub Pages), the app can be installed from the browser ("Install app" / "Add to Home Screen"). A service worker (`web/sw.js`) then:

- stores the app shell — code, styles, all fonts and icons — on first visit, so the app always opens offline;
- keeps every text that has been read (`data/*.json`) and refreshes it in the background when online;
- lets Settings → Offline download a whole Veda, or the Sāyaṇa bhāṣya, ahead of time, using the file lists in `web/data/offline.json`.

Nothing else needs the network: the pañcāṅga is computed on the device and location comes from the device.

**Releasing a new version:** bump `version` (and `released`) in `web/version.js` and add an entry to `CHANGES` in `web/app.js` and to `CHANGELOG.md`. The version change makes installed copies fetch the new app shell on their next visit and offer a reload; stored texts are kept.

## Using the app

- **Back** returns to the previous view (or the parent, when opened from a link); next/previous moves replace the view instead of adding back steps; sheets and the chant view close on Back.
- **Options bar**: under the top bar, the settings that apply to the page (script, menus, theme, pāṭha, padapāṭha, IAST, tags, translation, bhāṣya, text size, save, chant); ⋯ opens them all with labels.
- **My sūktas**: ☆ in the options bar saves a sūkta; the My sūktas tab shows My list · Recent · Frequent. Stored only on the device (`localStorage`, key `vedalokana.my`); export/import in Settings.
- **Search**: one box, in English, Devanagari or Kannada (spellings are folded to one key by `web/search-key.js`). It takes a reference (`1.164.46`, `rv 10.90`, Devanagari or Kannada digits), a name (`agni suktam`, `rudram`, `श्रीसूक्तम्`), a deity, seer or metre alone or two together (`indra trishtup`), an everyday word (`hymn to dawn`), the first words of a mantra (`tryambakam yajamahe`) or any few of its words (`ekam sad viprah bahudha`; Saṃhitās and Upaniṣads). Results are grouped (Mantras, Sūktas, Texts and parts, Ṛṣi · devatā · metre); the Search page has a Veda filter. Details under *Search* below.
- **Daily mantra**: on Home, five cards to swipe through — mantra, meaning, words and grammar, ṛṣi · devatā · chandas, use and significance (English, or Kannada with the Kannada script); 365 mantras, ↻ for another. Built by `node scripts/build-daily.mjs` from `scripts/daily/`.
- **Chant view**: a book-style page (running text, ॥n॥, invocation, source, anukramaṇī) or one verse at a time.

## Rebuild the data

The JSON in `web/data` is generated by `scripts/build-data.mjs` (Node 18+, no dependencies) from five public repositories. The per-text parsers live in `scripts/texts.mjs`.

```sh
git clone --depth 1 https://github.com/031323/vedaweb-data
git clone --depth 1 https://github.com/mahesh-ak/WSC2023
git clone --depth 1 https://github.com/bhavykhatri/DharmicData
git clone --depth 1 https://github.com/sanskrit/raw_etexts
git clone --depth 1 https://github.com/sanskrit/gretil-mirror

node scripts/build-data.mjs \
  --vedaweb vedaweb-data \
  --anukramani WSC2023/Anukramani \
  --dharmic DharmicData \
  --raw raw_etexts \
  --gretil gretil-mirror \
  --sayana sa.wikisource.org/rigveda/rigveda.vyview \
  --out web/data
# also writes web/data/offline.json (node scripts/offline-index.mjs does just that step)
# --sayana is optional: git clone -b gh-pages https://github.com/project-vyasa/sa.wikisource.org
```

## Fonts

`web/fonts/` holds the Sanskrit fonts — Noto Serif Devanagari, Noto Serif Kannada and Shobhika (IIT Bombay) — each in two builds: `*-Vedic.woff` with svara marks drawn about twice as thick, and `*-Std.woff` with the font's own strokes ("Standard" in Settings). In both, every anudātta is anchored at one depth under the line instead of hanging from each letter (which made the bars step up and down), going lower only under a letter that reaches deeper. There are also Latin/IAST subsets of IBM Plex Sans and Gentium Book Plus, so no font server is needed. All are built from a checkout of [google/fonts](https://github.com/google/fonts) and the [Shobhika release](https://github.com/Sandhi-IITBombay/Shobhika/releases):

```sh
python3 scripts/make-fonts.py path/to/google-fonts web/fonts --shobhika path/to/Shobhika-1.05 --audit /tmp/afonts   # needs fontTools
node scripts/audit-marks.mjs /tmp/afonts   # anudātta depth, clearance and line extents over all the data (Playwright)
```

## Ṛgveda pāṭhas

The Ṛgveda can be shown two ways (Settings, or the switch in the reader):

- **Dākṣiṇātya pāṭha** (default) — as South Indian (Karnataka) recitation books print it:
  - a svarita on a heavy syllable gets the double stroke ᳚ (dīrgha svarita);
  - a class nasal inside a word is written as anusvāra (इंद्र, क्षु॒मंतं᳚), while one at the end of a word keeps its letter (म॑घवञ्चि॒त्रम्);
  - where two pādas run together, the swallowed a gets an avagraha (दक्षि॑णेना॒ऽभि, वृ॒त्वाऽत्य॑तिष्ठत्);
  - a kampa is written with its vowel in brackets, then the rest of the syllable and the numeral: र॒प्स्व(अ॒)न्१॒॑तः.
- In the Atharvaveda and the Vājasaneyi Saṃhitā the Dākṣiṇātya pāṭha applies only the nasal rule (there is no padapāṭha for them here); the Taittirīya texts keep their own pāṭha.
- **Antarjāla pāṭha** — the text as published by VedaWeb (after Aufrecht): every svarita with one stroke ॑; a kampa as १/३ with anudātta and svarita.

The Dākṣiṇātya pāṭha is computed in the browser by `web/dakshinatya.js`; the rules are written out at the top of that file. Word boundaries come from aligning each ṛk with its padapāṭha, and pāda boundaries from the syllable count of the half-verse. The dīrgha-svarita rules were derived from, and are tested against, Dayananda Aithal's [Saswara Rigveda Samhita](https://github.com/daithal/saswara-rigveda), whose dīrgha svaritas were themselves added by program: on all 10,552 ṛks they agree on 99.99% of svarita marks. No text is copied from that site. The other rules were read off printed Gaṇapati, Hiraṇyagarbha, Puruṣa and Devī sūktas, which the test reproduces exactly.

## Dictionary

`#/kosha` is a browsable, searchable Sanskrit → Kannada dictionary (Śabdārtha Kaustubha), also reached from the Library page and as a "Dictionary" group in search results. Build it with `node scripts/build-kosha.mjs <shabdArtha_kaustubha.babylon>`; the source file, its licence question and the limits are in `docs/DATA_SOURCES.md`.

## Search

Everything runs in the browser from small files in `web/data/search/`, built by `node scripts/build-search.mjs` (also run by `build-data.mjs`; it works on the data already in `web/data`):

| File | Holds | Loaded |
|---|---|---|
| `names.json` | sūktas and their aliases, texts, named parts, every ṛṣi · devatā · chandas | at the first query, stored on install |
| `../search-aliases.json` | kind, facet, Veda, everyday and stop words | at the first query, stored on install |
| `pratika.tsv` | the first three words of every mantra | for queries of seven letters or more, stored on install |
| `text-<veda>.tsv` | one line per mantra: its whole phonetic key | when a query has two or more words that are not names; part of that Veda's offline download |

- Sūktas get their aliases in `scripts/suktas.mjs`; the other word lists are in `scripts/search-aliases.json` (hand-edited; any script, they are folded to one key). Both are checked at build time.
- Saṃhitā and Upaniṣad mantras are indexed (23,744); Brāhmaṇas and Āraṇyakas are not.
- Ranking: a reference first; then, for the opening words of a named mantra, the verse and then the sūktas it belongs to; names before mantras that merely begin with them; exact before prefix before inside a name.
- `web/search.js` (no DOM) is run unchanged by the tests; `scripts/search-tests.json` holds 73 queries with the expected first result (`scripts/search-tests.md` explains the fields).

## Tests

```sh
node scripts/test-lipi.mjs   # Devanagari → Kannada: word checks + every line of the data
node scripts/test-dakshinatya.mjs [path/to/saswara-rigveda]   # Dākṣiṇātya pāṭha vs. printed sūktas (and Aithal's edition)
node scripts/test-search-key.mjs     # spellings that must fold together, every verse Devanagari vs IAST, Kannada round trip
node scripts/test-names.mjs          # names index: seed names in four spellings
node scripts/test-query.mjs          # query parser, result groups, highlighting
node scripts/test-mantra-index.mjs   # every verse indexed, openings and middles found
node scripts/test-search.mjs --check-baseline --min-top1 0.85 --min-top5 0.95   # 73 queries through the real search
node scripts/test-kosha.mjs          # dictionary data: every shard, lookups, search rows in three scripts
node scripts/check-search-fresh.mjs # committed search indexes match a fresh build (add --fix to rebuild them)
node scripts/test-all.mjs            # all of the above
```

**Keeping the search indexes current.** `web/data/search/` and `search-aliases.json` are generated. The check above fails if they are stale, and it runs in three places: the `Checks` workflow (every pull request and push to `main`), the deploy workflow (a stale index blocks the deploy), and a local pre-commit hook that rebuilds and stages them when a commit touches their inputs. Enable the hook once per clone with `git config core.hooksPath .githooks`. Claude Code sessions in this repo rebuild them after edits to the inputs (`.claude/settings.json`).

## Standalone Dictionary app (`web/kosha/`)

The Dictionary is also an app of its own at `kosha/` (Śabdārtha Kaustubha, installable, own icon, own service worker with the scope `kosha/`).
- Screens: `web/kosha-ui.js` is shared by Vedāvalokanam (`web/app.js`) and the standalone app (`web/kosha/app.js`).
- Versions are separate: `web/version.js` (Vedāvalokanam) and `web/kosha/version.js` (standalone). A change to `kosha-ui.js`, `kosha.js`, `styles.css` or `data/kosha/` reaches both apps: bump both. A change only inside `web/kosha/` bumps only `web/kosha/version.js`.
- Offline: both apps keep dictionary data in the same cache (`vedalokana-data`), so one download serves both.
- `node scripts/test-kosha-app.mjs` checks the app's files, manifest, icons and service-worker list.
